SupportBot — Presenter Cheat Sheet

Youssef Bassem · Mahmoud Alsayed · Somaya Ahmed  |  19 slides · ~10–12 min  |  Rule: say the short line, then stop talking.
SupportBot turns Elsewedy's resolved support cases into a shared memory any field engineer can search in plain language, in seconds.
1. Cover. We're Youssef, Mahmoud & Somaya. SupportBot helps Elsewedy field engineers find a device fix in seconds, from past cases. (2 sentences, stop.)
2. The problem. The fix usually exists — in an old ticket or a senior's head — but reaching it means asking around and waiting. 1 in 3 of our cases repeat a solved problem; knowledge leaves when people leave. SupportBot makes it searchable.
01 · The Product — "First, what it does for an engineer."
4. Find the fix. Describe the problem in plain words. Searches 66 cases / 7 products / 8 categories by meaning, not keywords. Type a product name → count of past cases. Suggested questions to start.
5. Cited answers. Every answer cites the exact case — ID, original problem, the real resolution. Copy it, or rate helpful / not helpful.
6. It remembers. Follow-ups understood in context ("does it happen on the X100 too?") — never restate the problem. Still cited.
7. Shows its work. "See how this was found" opens the search space — each dot a case, highlighted = what you matched. Shows why, doesn't ask for blind trust. (Our signature feature — pause here.)
02 · Trust — "Trust what it says, and what it refuses to say."
9. Stays in scope. Declines general-knowledge questions. If nothing matches, it says so — never dresses up an unrelated case as an answer.
10. Small talk. Warm reply to greetings, then steers back. Never invents a fake Case ID — citations appear only for real cases.
11. Always answers. If the AI writer is down, it still lists matching cases in full. Degrades gracefully — no error screen.
12. How we measured it. ⭐ A 15-question test set (5 model-number, 7 plain-words, 3 out-of-scope), each labelled with the correct case. Right case first every time; refuses every out-of-scope. Runs in CI. Cutoff 0.735 sits in the clear gap (answerable ≤0.582, out-of-scope ≥0.874).
13. Why hybrid. Meaning search = 100% but blurs G2/G3; keyword keeps exact numbers distinct but 71%. We merge both — for exact-number robustness, honestly not a higher score here.
03 · The Experience — "What makes it usable on a real day."
15. Fully bilingual. One toggle → full English/Arabic, true right-to-left, remembered. Ask in Arabic → answer in Arabic. Proper Arabic font.
16. Light and dark. One click re-themes; follows the OS, remembers your choice. Contrast-checked, visible keyboard focus, reduced motion.
17. On any screen. Full experience down to phone width. Single column, nothing cut off. Sidebar → slide-in drawer; opens from the correct side in Arabic.
18. Your account. Real account, stay signed in through a refresh. Password reset by emailed code. Protected against repeated guessing.
19. Thank you. The company's own cases, a searchable memory in seconds. "Thank you — we'd love your questions." Then stop and let them ask.

Defending the perfect score

  • Offer to run it live: uv run python -m eval.eval_retriever — also runs in CI on every commit.
  • It's a 15-question safety check (regression gate), not a benchmark. Correct answers are fixed to the case text, not to what the system returned.
  • Faults repeat across products → some questions have several correct answers → 100% is honest, not luck.
  • Earlier ~0.77: fixed keyword filler-word scoring + completed 9 cases (57→66). Keyword-alone still ~0.71 on paraphrase — exactly why we don't ship it alone.
  • Say the limit unprompted: "Perfect means our test set is green, not that it's solved. Next step: a bigger, independently-labelled test set."

30-sec version: Field engineers waste time re-solving problems the company already solved — 1 in 3 of our cases is a repeat. SupportBot lets any engineer describe a problem in plain language, English or Arabic, and get the exact past fix, with the case cited so they can trust it. It refuses when it doesn't know, shows its own reasoning, and we measured it: on our 15-question test set it returns the right case first every time and refuses every out-of-scope question — checked automatically on every code change.
